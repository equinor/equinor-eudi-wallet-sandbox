# Equinor EUDI Wallet Sandbox — Site Skill

Guidance for working on the static informational site that tells relying parties
about Equinor's work with the EU Digital Identity (EUDI) Wallet sandbox hosted by
Digdir. The site is plain HTML/CSS/JS with **no build step**, deployed to **Azure
Static Web Apps** from the `equinor/equinor-eudi-wallet-sandbox` GitHub repo.

## When to use this skill

- Editing site content or sections (Overview, Relying parties, Equinor's role, Resources, Contact & FAQ).
- Adjusting styling, navigation, or the 404 page.
- Previewing the site locally.
- Changing routing/security headers or the Azure deployment configuration.

## Project structure

```
.
├── index.html                 # Single-page site; ALL content lives here
├── 404.html                   # Custom not-found page
├── css/styles.css             # Styles (Equinor theme via CSS variables in :root)
├── js/main.js                 # Mobile nav toggle + footer year
├── staticwebapp.config.json   # Azure SWA routing fallback + security headers
├── README.md                  # Human-facing setup/deploy notes
└── .github/workflows/         # Auto-generated by Azure SWA (deploys on push to main)
```

## Core conventions

- **No build tooling.** Do not introduce a bundler, framework, or `package.json`
  unless the site's requirements genuinely change. Files are served as-is from `/`.
- **Content edits go in `index.html`.** Sections are anchored (`#overview`,
  `#relying-parties`, `#equinor-role`, `#resources`, `#contact`). Keep the nav
  list in `<nav>` in sync with section IDs.
- **Theme via CSS variables.** Colors and layout tokens are defined in `:root` in
  `css/styles.css`. Reuse existing variables instead of hardcoding values.
- **Accessibility.** Preserve the skip link, `aria-*` attributes on the nav
  toggle, semantic headings (one `<h1>`, section `<h2>`s), and visible focus.
- **Sandbox disclaimer.** The site must keep stating that the sandbox is for
  testing/experimentation only — not a production identity service. Do not remove
  the disclaimer in the hero, the callout, or the footer.
- **External links** open in a new tab and MUST include `rel="noopener noreferrer"`.
- **Security headers** live in `staticwebapp.config.json`. If you add external
  images, scripts, or styles, update the `Content-Security-Policy` accordingly
  (it is currently `'self'`-only plus `data:` images).

## Run locally

No tooling required — open `index.html` directly, or serve the folder:

```powershell
python -m http.server 5500   # then open http://localhost:5500
# or
npx serve .
```

## Deploy (Azure Static Web Apps)

Continuous deployment: pushing to `main` triggers the Azure-generated GitHub
Actions workflow. Build configuration for this no-build site:

| Field           | Value        |
| --------------- | ------------ |
| Build Presets   | `Custom`     |
| App location    | `/`          |
| Api location    | *(empty)*    |
| Output location | *(empty)*    |

After Azure creates the app it commits a workflow under `.github/workflows/`;
run `git pull` to sync it locally.

## Guardrails

- Keep the content factual; verify sandbox onboarding specifics with Digdir before
  publishing claims about the process.
- No secrets, personal data, or production credentials belong in this repo.
- Test nav, links, and the 404 page after structural changes.
